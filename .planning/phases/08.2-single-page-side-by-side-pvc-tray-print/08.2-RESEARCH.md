## 1. Executive Summary & Operator Workflow Analysis

### The Problem
When clicking **"Print PVC Tray"**, the print spooler generates a 2-page print document:
- **Page 1:** Front card canvas ($85.60\text{ mm} \times 53.98\text{ mm}$)
- **Page 2:** Back card canvas ($85.60\text{ mm} \times 53.98\text{ mm}$)

As evidenced in the operator print artifact `docs/PrintPortal Next.js | Official Standard PVC Card Printing Gateway copy.pdf`:
The operator's physical setup (Epson L805 / L850 / Canon G-series PVC card trays or A4 PVC dragon sheet laminates) expects **both Front and Back cards to print side-by-side in a single printer pass on ONE PAGE**.

### Physical Tray & Hardware Reality
1. **2-Card Multi-Purpose Tray Mechanics:**
   - Desktop inkjet PVC printers (Epson L805, L850, L8050, Canon G1010/G2010) feed a physical plastic card tray through the manual CD/DVD tray slot.
   - The tray contains **two physical card slots**:
     - **Slot 1 (Left):** Front of the ID card ($85.60\text{ mm} \times 53.98\text{ mm}$)
     - **Slot 2 (Right):** Back of the ID card ($85.60\text{ mm} \times 53.98\text{ mm}$)
   - The tray feeds through the printer **once per print job**.
   - If the software generates a 2-page print job:
     - The printer prints Slot 1 on Page 1, automatically ejects the tray, and halts awaiting a second tray insertion for Page 2.
     - Slot 2 on the tray remains completely unprinted, and a second tray pass is wasted.
2. **Sheet & Laminate Pouch Printing:**
   - Operators using photo paper, PVC dragon sheets, or teslin sheets print Front and Back side-by-side on a single A4/Letter page, cut them with a manual card cutter or scissors, fold them down the center line, and run them through a thermal laminator.
   - A 2-page print job wastes an entire sheet of expensive synthetic PVC core paper.

## 2. Root Cause of the 2-Page Split

### Root Cause 1: Explicit `page-break-after: always` between Front and Back Cards
In `src/components/cards/Cr80CardContainer.tsx`:
```tsx
{/* Print Mode Containers */}
<div className="hidden print:block w-full">
  {/* Page 1: Front Card */}
  <div className="cr80-print-tray">
    <div className="w-[85.6mm] h-[53.98mm] relative overflow-hidden bg-white">
      {front}
    </div>
  </div>

  {/* Page 2: Back Card */}
  <div className="cr80-print-tray">
    <div className="w-[85.6mm] h-[53.98mm] relative overflow-hidden bg-white">
      {back}
    </div>
  </div>
</div>
```
In `src/app/globals.css`:
```css
.cr80-print-tray {
  width: 85.6mm !important;
  height: 53.98mm !important;
  page-break-after: always;
  break-after: page;
  ...
}
```
- The Front and Back cards are rendered as distinct, vertically stacked block elements where the front card forces a page break (`break-after: page`).
- This guarantees that Front and Back are separated onto two distinct pages.

### Root Cause 2: `@page` Rule Restricts Width to a Single Card ($85.6\text{ mm}$)
In `src/app/globals.css`:
```css
@page {
  size: 85.6mm 53.98mm;
  margin: 0;
}
```
- A global `@page` rule with `size: 85.6mm 53.98mm` tells Chromium and WebKit that the paper is only $85.6\text{ mm}$ wide.
- Even if two cards are placed side-by-side ($85.6\text{ mm} \times 2 = 171.2\text{ mm}$), they exceed the declared page width of $85.6\text{ mm}$, forcing the browser to wrap or spill the second card onto Page 2.

## 3. Prescriptive Solution Blueprint

### 1. Refactor `Cr80CardContainer.tsx` to a Single-Page Flex Row
Replace the stacked `.cr80-print-tray` elements with a horizontal flex row container:
```tsx
{/* Print Mode Container: Single Page Side-by-Side (Front on Left, Back on Right) */}
<div className="hidden print:block w-full">
  <div className="cr80-print-tray-row">
    {/* Slot 1: Front Card (85.60mm x 53.98mm) */}
    <div className="cr80-print-card-slot">
      <div className="w-[85.6mm] h-[53.98mm] relative overflow-hidden bg-white">
        {front}
      </div>
    </div>

    {/* Slot 2: Back Card (85.60mm x 53.98mm) */}
    <div className="cr80-print-card-slot">
      <div className="w-[85.6mm] h-[53.98mm] relative overflow-hidden bg-white">
        {back}
      </div>
    </div>
  </div>
</div>
```

### 2. Update CSS in `src/app/globals.css`
1. **Relax `@page` to Support Horizontal Dimensions:**
   ```css
   @page {
     size: auto;
     margin: 0;
   }

   @page cr80-sheet {
     size: 171.2mm 53.98mm;
     margin: 0;
   }
   ```
   Setting `@page { size: auto; margin: 0; }` allows the printer driver to use the operator's actual paper/tray profile (A4 portrait, A4 landscape, CD/DVD PVC tray) without artificially clamping the page width to $85.6\text{ mm}$.

2. **Style `.cr80-print-tray-row` and `.cr80-print-card-slot`:**
   ```css
   /* Single-Page Side-by-Side PVC Tray Print Engine */
   .cr80-print-tray-row {
     display: flex !important;
     flex-direction: row !important;
     align-items: flex-start !important;
     justify-content: flex-start !important;
     gap: 5mm !important; /* Calibrated tray gap */
     width: max-content !important;
     margin: 0 !important;
     padding: 0 !important;
     page-break-inside: avoid !important;
     break-inside: avoid !important;
     page-break-after: avoid !important;
     break-after: avoid !important;
   }

   .cr80-print-card-slot {
     width: 85.6mm !important;
     height: 53.98mm !important;
     margin: 0 !important;
     padding: 0 !important;
     page-break-inside: avoid !important;
     break-inside: avoid !important;
     page-break-after: avoid !important;
     break-after: avoid !important;
     overflow: hidden !important;
     position: relative !important;
     box-sizing: border-box !important;
     background: #ffffff !important;
   }
   ```

3. **Total Width Math on A4:**
   - Front Card: $85.60\text{ mm}$
   - Gap: $5.00\text{ mm}$
   - Back Card: $85.60\text{ mm}$
   - Total Width: $176.20\text{ mm}$
   - A4 Paper Width: $210.00\text{ mm}$ (margin remaining: $33.80\text{ mm}$)
   - Total Height: $53.98\text{ mm}$
   - Both cards fit comfortably side-by-side within a single page with zero overflow and zero page breaks.
